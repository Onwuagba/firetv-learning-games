# Fire TV Learning Games

Amazon Developer Hackathon 2026 — **Fire TV track**. Three remote-friendly learning games for
kids on the shared curriculum: a D-pad abacus, a countries and capitals quiz, and algebra balance
scales. Progress syncs with the Alexa+ Learning Coach, so practice by voice shows up on the TV.

## What's here

**`app/` is the real Fire TV app**: Expo + React Native for TV (`react-native-tvos` 0.81), forked from Amazon's
[react-native-multi-tv-app-sample](https://github.com/AmazonAppDev/react-native-multi-tv-app-sample) (MIT-0, see `NOTICE`).
- Focus: `react-tv-space-navigation` (same library as the sample). One `SpatialNavigationRoot` per screen, a shared `Focus` component gives every element the same yellow ring, lift and glow. Home remembers the last tile.
- Remote input: `app/tv/` (from the sample): Android key events via `react-native-keyevent`, keyboard on web (arrows, Enter/Space = OK, Esc/Backspace = BACK).
- BACK: `src/nav.ts` stack. Pops to home from any game, on home it defers to the system (exit). Android BACK is read from both the key event and `BackHandler` (deduped).
- Screens (`app/src/screens`): Home (3 tiles with level/score), Abacus (on-screen beads, rods are focus targets, Up/Down slide beads), Map Quiz (offline SVG world map highlights the country, 2x2 focus grid), Balance Scales (SVG beam tilts by `tiltDegrees`).
- Map: `app/src/mapData.ts` generated by `scripts/gen-map.mjs` from Natural Earth 110m (177 countries, ~90 KB, offline). `react-native-svg` is the only rendering dependency.
- Large type, 5% title-safe margins, remote hint bar on every screen, 1920x1080 design scaled with `react-native-pixel-perfect`.
- Level-up locally: `STREAK_TO_LEVEL_UP` (2 correct in a row, same as the coach's `PROMOTE_AFTER`), applied optimistically by `ProgressSync`. With a coach connected, the coach decides levels and its numbers replace the local guess on the next sync. The Abacus screen reads its level from `ProgressSync` (no random level-ups).

Shared, pure, tested logic (reused unchanged by both `app/` and the old web preview):
- `src/curriculum.ts` + `.json`, `src/games/` (`abacus`, `quiz`, `balance`), `src/focus/grid.ts`, `src/nav.ts`, `src/progress/` (`ProgressSync` with offline queue; `MockProgressClient` is the fallback, `HttpProgressClient` talks to the coach's TV REST API, see below).
- Metro maps the `.js` import suffixes in `src/` back to `.ts` (`app/metro.config.js`); `structuredClone` is polyfilled in `app/index.js`.

Also: `src/ui/` + `preview/` (React DOM preview, older), `docs/`.

```bash
npm install && npm test && npm run typecheck     # logic tests (16) + tsc for src/
npm run app:install && npm run app:typecheck     # app deps (npm, --legacy-peer-deps) + tsc for app/
npm run app:web                                   # http://localhost:8082, keyboard = remote
```

## Run on Fire TV / Android TV (NOT yet run, no Android SDK on the dev machine)

Requirements: JDK 17, Android SDK (platform 36, build-tools), an Android TV or Fire TV emulator / device with ADB enabled.
```bash
cd app && npm install --legacy-peer-deps
EXPO_TV=1 npx expo prebuild --clean --platform android   # verified to run: generates android/ with LEANBACK_LAUNCHER and KeyEvent hooks
EXPO_TV=1 npx expo run:android                            # builds and installs on the connected emulator/device
# Fire TV device over network:  adb connect <fire-tv-ip>:5555  (Developer options > ADB debugging)
```

## Connect to the Alexa+ Learning Coach

Set env vars before `npm run app:web` (Expo inlines `EXPO_PUBLIC_*` at bundle time):

```bash
EXPO_PUBLIC_COACH_URL=http://127.0.0.1:8000 EXPO_PUBLIC_TV_TOKEN=<coach TV_API_TOKEN> EXPO_PUBLIC_CHILD=ada npm run app:web
```

- No `EXPO_PUBLIC_COACH_URL` = mock client (still persisted locally). `EXPO_PUBLIC_CHILD` defaults to `demo-learner`; use the same child name you use with Alexa+.
- Local state (progress + unsent answers) lives in AsyncStorage, so it survives restarts and unsent answers sync when the coach is reachable. The app retries and re-pulls every 8 s, so progress made by voice appears without restarting.
- Corner badge: `Local only` / `Syncing...` / `Synced with coach` / `Offline - will sync (n queued)`.
- Contract (defined in the coach repo, `learning_coach/tvapi.py`): `GET /api/progress/{child}`, `POST /api/progress/{child}/events` with `{events:[{id,topic,correct,at}]}`, bearer `TV_API_TOKEN`. Events carry ids so retries are not double counted; the TV cannot set levels or unlock topics (locked topics' events are rejected by the coach).
- The token is baked into the app bundle (anyone with the bundle can read it); it only reaches the TV API. Use HTTPS for anything but localhost. On a real Fire TV use the coach's LAN/HTTPS address, not 127.0.0.1 (native: not tested; Android may block cleartext http, TODO-verify).
- Integration test: `npm test` starts the real coach from `../alexa-learning-coach/.venv` (skipped if absent), plays the child over MCP and checks the TV client sees and pushes progress. Screenshots: `docs/screenshots/20-...`, `21-...` (Level 1 then Level 2 after two answers given through the coach).

## Verified vs not

Verified: root tests (20 pass, incl. local coach integration) and the web target against a locally running coach (headless Chrome screenshots 20/21); earlier: root tests and typecheck; `app/` typecheck; web target in headless Chrome (all four screens, arrow-key focus, Enter, Esc/Backspace back, screenshots in `docs/screenshots/`); `expo prebuild --platform android` succeeds and produces a leanback launcher manifest and the KeyEvent MainActivity hooks.
NOT verified: any native Android/Fire TV build or run, real remote key codes, `BackHandler` on Fire OS, tvOS, performance on a Fire TV Stick, Kotlin/Gradle build of the prebuilt project.

## Known gaps

- Live link is only tested against our own coach on localhost via the web target; the native Fire TV build with the coach is NOT tested. Alexa+ itself is not involved (the child's side is simulated over MCP by `alexa-learning-coach/scripts/demo_tv.py`).
- Streak dots use 3-in-a-row while the coach uses 2, so dots and coach levels can disagree until the next sync.
- Poll is 8 s; a lower-level answer made while another client changed the same child is resolved by the coach (server wins).
- Sync loop and status badge are not unit tested (UI); AsyncStorage on native untested.
- `react-native-tvos` is the fork of RN, so `expo install --check` reports a version mismatch for `react-native` (expected; excluded via `expo.install.exclude`).
- Balance scales: OK on an unbalanced scale counts as a wrong attempt; auto-solve on balance is the reward. Level 4 (`ax + b`) draws `a` identical x blocks.
- Map shows the country outline plus a ring; very small countries rely on the ring. No pan or zoom.
- Not tested: accessibility services (TalkBack) beyond labels being set.
